# FlowDAgger × LIBERO-Recovery：实现说明

这套代码用 LIBERO 的示范数据训练一个小网络，让它引导 π0.5 完成任务。π0.5 的权重保持固定，每个任务单独训练一个小网络。这个小网络在代码里叫 **steering**。

想运行实验，直接看[使用教程](libero_offline_usage.md)。本文介绍它怎么工作，以及代码放在哪里。

## 整体上做什么

π0.5 从一块噪声出发，结合相机图像、机器人状态和任务指令，逐步生成动作。FlowDAgger 学的是：**在当前观测下，给 π0.5 什么样的起始噪声，更容易生成想要的动作。**

整个过程分三步：

1. **准备训练标签。** 读取示范中的观测和动作，反过来求出能产生这些动作的噪声。这一步叫“动作反演”。
2. **训练 steering。** 输入观测特征和机器人状态，学习预测刚才求出的噪声。
3. **闭环评测。** 小网络预测噪声，π0.5 根据噪声生成动作，仿真环境执行动作后再返回新观测。

```text
训练：示范观测 + 示范动作 → 动作反演 → 噪声标签 → 训练 steering

评测：环境观测 → steering 预测噪声 → π0.5 生成动作 → 环境执行
         ↑                                              │
         └──────────────── 新观测 ──────────────────────┘
```

Base 对照直接使用随机噪声；steering 使用小网络预测的噪声。两种方式共享同一个 π0.5。

## 数据怎么用

数据来自 `LIBERO-Recovery/datasets/plus_featured`，分为两类：

| 数据 | 内容 |
|---|---|
| Standard | 从普通初始状态开始完成任务的示范 |
| Recovery | 从失败状态继续完成任务的恢复示范 |

默认把两类数据混合起来，每个任务训练一个 steering。也可以只用 Standard 或只用 Recovery，比较两种数据各自的效果。

当前数据集有 10 个任务：编号 0–7 来自 LIBERO-90，8 来自 LIBERO-Goal，9 来自 LIBERO-Object。这里的任务编号取自 `data_pool.json`。评测也分 Standard 和 Recovery，区别在于环境从普通初始状态还是保存的失败状态开始。

训练时，每个任务的两类示范分别按整条轨迹划分：80% 用于训练，20% 用于验证。每条轨迹再切成连续 10 步的动作片段。混合训练时，Standard 和 Recovery 各占约一半；选定来源后，先选轨迹，再选轨迹里的片段。

## 三个目录怎么分工

| 目录 | 负责什么 |
|---|---|
| `FlowDAgger/flowdagger_pi05/libero_offline/` | 算法核心：数据读取、动作反演、小网络训练和策略推理 |
| `FlowDAgger/flowdagger_pi05/flow_recovery/` | 实验运行：生成配置、分配 GPU、启动训练与评测、查看进度和汇总结果 |
| `LIBERO-Recovery/examples/flowdagger/` | 仿真客户端：设置场景、发送观测、执行动作、记录成功与失败 |

`flow_recovery` 调用另外两部分，把一轮实验串起来。日常运行可以用这一层；修改算法时主要看 `libero_offline`，修改环境行为时看仿真客户端。

### 算法核心：libero_offline

| 文件 | 功能 |
|---|---|
| `data.py` | 读取示范，划分训练/验证轨迹，切动作片段，给训练提供样本。 |
| `bridge.py` | 连接 π0.5：处理输入、提取图像和语言特征、反演动作、调用动作生成器。 |
| `precompute.py` | 批量计算特征和噪声标签，按轨迹保存到缓存。中断后可以接着算。 |
| `actor.py` | 创建 steering 网络，保存和恢复模型、优化器及随机数状态。 |
| `train.py` | 为每个任务训练 steering，记录训练和验证误差，定期保存模型。 |
| `serve.py` | 启动策略服务。收到观测后，按 `task_key` 选择小网络，返回动作。支持 Base 和 steering 两种模式。 |
| `common.py` | 读取配置、解析路径、读写 JSON，以及生成缓存标识。 |
| `transport.py` | 提供适合长时间编译和渲染的 websocket 连接选项。 |

`bridge.py` 复用 OpenPI 的输入输出处理和 FlowDAgger 的反演器，`actor.py` 复用已有的 `SteeringPolicy`。

预计算还会做一次回放检查：把求出的噪声交给 π0.5，看能否重新生成示范动作。重建误差合格的片段才进入训练缓存。这样，训练标签与实际推理使用的是同一条动作生成路径。

### 实验运行：flow_recovery

| 文件 | 功能 |
|---|---|
| `prepare_run.py` | 为一轮实验生成逐任务配置、Standard/Recovery 评测计划和 LIBERO 路径配置。 |
| `audit_data.py` | 检查示范数组、任务文本和数据完整性，输出检查结果。 |
| `schedule.py` | 根据空闲显存分配 GPU，安排多个任务运行。 |
| `run_task.py` | 执行一个任务的完整流程：预计算、训练、启动服务、预热、评测并关闭服务。 |
| `guarded_precompute.py` | 在加载大模型前检查显存，显存够了再开始预计算。 |
| `warmup.py` | 提前向服务发送一次请求，完成首次推理编译。 |
| `status.py` | 显示训练步数、缓存数量和评测完成情况。 |
| `cache_summary.py` | 汇总反演标签的接纳率、重建误差和噪声范围。 |
| `summarize.py` | 对照 Base/steering 的逐条结果，生成任务成功率、总体成绩和统计区间。 |

批量运行时，一个任务分配一张 GPU，模型计算和仿真渲染使用同一张卡。任务结束后，调度器把这张卡交给下一个任务。

### 仿真客户端：examples/flowdagger

| 文件 | 功能 |
|---|---|
| `protocol.py` | 读取任务列表，选取评测初态，确定随机种子，整理发给策略服务的观测。 |
| `evaluate.py` | 恢复初态、执行动作、判断任务是否完成，保存逐条结果和可选视频。 |
| `scene_compat.py` | 修复部分导出场景的 BDDL 声明，生成评测用副本。 |
| `recovery_env.py` | 为 Recovery 场景提供状态恢复方式，支持保存状态中的堆叠或抓持姿态。 |
| `setup_paths.py` | 生成本轮实验使用的 LIBERO 资源路径。 |
| `transport.py` | 连接策略服务。 |
| `requirements.txt` | 列出仿真客户端所需依赖。 |

Standard 评测读取 LIBERO 的原生初始状态；Recovery 评测读取场景 BDDL 和对应的 `sim_state.npy`，加上指定的物体位置扰动。环境先静置，再开始执行策略。

Base 和 steering 重放同一份评测计划，因此任务、场景、初态和扰动种子保持一致。

## 模型之间传什么

策略服务收到双相机图像、机器人状态和任务文本，返回一段动作：

| 数据 | 内容 |
|---|---|
| 相机图像 | agentview 和 wrist 两路 RGB |
| 机器人状态 | 8 个数：末端位置 3、轴角姿态 3、夹爪关节位置 2 |
| 任务文本 | 数据清单里的 `official_task_language` |
| steering 输入 | π0.5 提取的图像/语言特征，拼合机器人状态供小网络使用 |
| steering 输出 | `(10, 32)` 的起始噪声 |
| 环境动作 | `(10, 7)`，即连续 10 步的原生 LIBERO 动作 |

仿真图像在客户端旋转一次，与训练图像对齐。图像缩放、状态和动作归一化由官方 π0.5 配置处理。夹爪动作沿用 LIBERO 的定义：-1 打开，+1 关闭。

默认 steering 是三层、每层 256 单元的 MLP，使用 linear 输出；每个任务训练 4000 步。模型和训练参数都在 JSON 配置中，具体修改方式见[使用教程](libero_offline_usage.md#调整训练参数)。
